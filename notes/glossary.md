# 용어·약자 정리

> 대화 중 헷갈리기 쉬운 약자·기호를 모은 참조표. 프로젝트는 이 표를 기준으로 계속
> 진행하며, 진행 중 바뀔 수 있는 항목은 그때그때 이 문서를 갱신한다 (미확정이라 안
> 쓴다는 뜻이 아니라, 리서치 특성상 나중에 바뀔 수 있다는 뜻).

## 후보·레이어

| 약자 | 뜻 | 상태 |
|---|---|---|
| H | 할루시네이션 억제 후보 (Hallucination) | 작성 완료, phase1 검증 중 (`layers/candidates/H.md`) |
| S | 스코프 제한 후보 (Scope) | **프로젝트 결정 — 이 이름으로 진행 예정.** 아직 `layers/candidates/S.md` 미작성 |
| A | 모호할 때 되묻기 후보 (Ask) | **프로젝트 결정 — 이 이름으로 진행 예정.** 아직 `layers/candidates/A.md` 미작성 |
| H2 | H의 문구 변형 v2 (5-4 규칙: 후보당 변형 1회만 허용) | held-out 케이스(case_11~13)만 준비된 상태, 문구 자체는 아직 확정 전 |
| lang | 언어 강제 레이어. 3B는 고정 레이어, 7B는 후보로 격하(2026-09-04) | `layers/fixed/lang.md`에 있음. 7B용 `layers/candidates/lang.md`는 아직 없음 — phase1 재검증하려면 필요 (`notes/migration-plan.md` 참고) |

S/A는 guideline.md 2-1의 일반 위반 유형 정의(스코프 제한 위반, 모호할 때 되묻기 위반)에서
이름을 따온 것 — 실제 candidate 파일은 아직 없지만, 다음 후보를 이 이름으로 만들기로
프로젝트에서 정했다.

## 모델·실행

| 약자 | 뜻 |
|---|---|
| 3B / 7B | Qwen2.5-3B-Instruct / 7B-Instruct |
| N | 케이스당 반복 실행 횟수. **세대에 따라 다름**: 구식 baseline(`baseline/`) N=10, 신규 baseline(`runs/baseline/3b`) N=5, H phase1 N=5 |
| case_NN | 원 테스트셋 케이스. 01~10(원본) + 11~13(2026-09-04 추가, held-out 역할) |
| held-out (case_11~13) | H2 문구를 다듬는 데 참고 금지, H2 phase1 결과 확인용으로만 사용. 실제 ID는 `case_11`~`case_13` 그대로 — "holdout_NN" 같은 별도 파일명/ID 체계는 없음 |
| run_NNN | 한 케이스의 n번째 실행 결과 파일명 (`run_001.json` 등, 3자리 zero-padded) |
| post-hoc 타겟 | 결과를 보고 사후에 드러난 실제 타겟 (예: H의 7B 진짜 타겟은 case_01이 아니라 case_02로 사후 발견됨, `harness/ablation/H/7b/md/failure_review.md`). 레포에 이 용어 자체가 쓰인 건 아니고 현상을 가리키는 표현 |

## 가이드라인 문서 절 번호

| 참조 | 내용 |
|---|---|
| 0-A | 실행 전 고정 조건 (생성 파라미터, 문구 삽입 위치, 케이스 불변, 모델/버전 고정) |
| 0-B | "케이스는 타겟/비타겟 상관없이 항상 전체 실행" 규칙. 타겟/비타겟 태그는 해석에만 사용 |
| 1-a | 후보 하나는 행동 하나만 타겟팅 (여러 행동을 한 문구에 섞으면 효과 분리 불가) — 후보 *간* 역할 분리가 아니라 후보 *하나* 내부의 단일 초점 규칙 |
| 1-b | 관찰 포인트로 바로 매핑 가능해야 함 — 모호한 지시("더 신중하게") 금지, 텍스트에서 직접 확인 가능한 신호로 이어져야 함 |
| 1-c | 금지 + 대안을 같이 명시 (`~하지 마세요. 대신 ~하세요.` 기본형) |
| 1-d | 초기엔 기본형 1개만 작성. 강도 변형은 결과가 애매한 후보에 한해 나중에 |
| 1-e | 모듈형 문구 작성 — 독립적으로 완결된 명령문, 형식 통일, **고정 레이어가 담당하는 내용(예: 출력 언어)은 언급하지 않음**. "언어 언급 금지"는 이 원칙의 하위 규칙 중 하나 |
| 1-f | 타겟 케이스의 고유명사·특유 상황·예시를 문구에 넣지 않음 (괄호 여부와 무관, 케이스 특정 내용 전반이 대상) |
| 2-1 | 실패 유형 정의 라이브러리 (할루시네이션 / 스코프 제한 위반 / 모호할 때 되묻기). "확인된 정보 부정" 유형 추가는 **아직 미정** (추가 예정이 확정된 게 아니라 "프로젝트 결정 사항으로 남김" 상태, `harness/ablation/H/3b/md/failure_review.md`) |
| 2-4 | 사이드이펙트 등급 (경미/중간/중대) + 측정 축 3개(자동/수동/미정의 스캔) |
| 3 (3-1~3-5) | 반복 횟수(N) 산정·증량 규칙 |
| 4-1 | Phase 1은 고정 레이어 안 붙임(순수 baseline 대비), Phase 2는 매 단계 끝에 고정 레이어 붙임 |
| 4-2 | 순위 결정 방식 (Phase 1·Phase 2 공통 산식 — 비교 대상만 4-1에 따라 다름). 타겟 케이스 풀링 실패율, ③ Jeffreys 사후분포 기반 보수적 개선량(분위수) |
| 4-4 | 모델별로 순위가 다르면 **Phase 2 진행 순서(스택 순서)를 모델별로 따로 돌림** — 문구 자체를 나누는 게 아님 |
| 5-1 | Phase 1 탈락 기준: 효과 없음(증량 후에도), 또는 중대 사이드이펙트가 증량 후에도 재현 |
| 5-4 | 문구 변형은 후보당 1회만 (5-1 탈락 직전 후보에 한해) |
| 부록 A | 결과 파일 최소 필드 정의. 타겟 여부 필드명은 `target_flag` (`is_target` 아님), 그 외 `fixed_layer`/`case_id`/`run_idx`/`gen_params`/`judgment`/`side_effect` 등 |
| 부록 B | 순위·점수 계산 코드 (Jeffreys Beta(0.5,0.5) 사후분포, 보수적 개선량 분위수) |
